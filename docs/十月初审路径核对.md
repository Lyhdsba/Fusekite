# Fusekite 十月初审：申报路径核对

核对日期：2026-10-14。本文是初审准备依据，不是赛事方的资格确认或项目验收报告。

## 官方依据与两条路径

| 事项 | 十月月赛：维护已有项目 | 季度优秀社区项目：持续维护 |
| --- | --- | --- |
| 入口 | 十月官网允许原创、移植和已有项目，也允许维护非本人创建的旧项目；已有项目需本期实质新增 | 社区开发者主动报名，项目须已有一定可用性并持续维护 |
| 贡献者条件 | 官网要求可追溯的实质贡献，不要求项目由参赛者创建 | 章程 4.2 要求主要贡献者为参赛者本人，允许其他贡献者；不要求当季新建或个人独立完成 |
| 历史成果 | 不重复计入当期工作；章程允许此前参赛项目凭新的、独立可验证成果重报 | 以本届期间新增有效贡献/维护为主要依据，历史代码量与完成度不能替代新增贡献 |
| 支持与季度入池 | 官网说明月度启动/完成支持及新项目通过验收后进入季度评选；旧项目如何衔接不能直接推定 | 章程将季度社区维护与新项目基础共建激励分别列示；主动报名不等于已入围或获奖 |

来源：[十月官网参赛流程、季度评选与参赛须知](https://moonbitlang.github.io/Hackathon2026/#process)；[正式章程第 4、5、6 节及申报要求](https://bxup9uklfcb.feishu.cn/wiki/Dx4Bwd6D1i3GfHkajQCcF7SznEd)。官网当前写明十月报名/验收截止 2026-10-31、沿用报名表、最多三次提交，以通过审核前最后一次有效提交或修改时间为准。章程读取版本的赛程部分仍显示九月日期；不能把九月日程套到十月，也不能自行消除官网与章程的口径差异。

**当前建议：** 以“十月月赛：已有项目实质新增，已实现可验证 POS”准备初审；将季度维护作为另行确认的路径，不自称“十月新建项目”或已自动取得季度资格。

## 提交前由参赛者向赛事方确认

1. 九月未通过的 Fusekite 按已有项目在十月修改原问卷重报时，应选择哪个字段？九月提交是否占十月三次额度？公开规则没有明确这一跨期计数口径。
2. 月赛旧项目能否申请启动/完成支持，通过本期审核后是否自动进入季度池，还是须另报季度社区维护？官网自动入池条目明确写的是月度新项目。
3. 本项目代码与材料有实质 AI 辅助。Git author/committer 署名只能证明发布账号；季度“主要贡献者”认定及人工申报书要求的具体执行方式，应以赛事方答复为准。

章程要求申报书由参赛者人工撰写且限一页 Markdown；因此[十月准备稿](十月黑客松申报草案.md)只能作为素材，须由参赛者独立改写、核对九月原始拒绝通知并确认理解技术方案。本次未代提交报名表或联系赛事方。
