# Fusekite 十月初审：申报路径核对

核对日期：2026-10-15。范围为初审准备，不代表赛事方资格确认或最终验收。

## 官方依据与两条路径

| 事项 | 十月月赛：维护已有项目 | 季度优秀社区项目：持续维护 |
| --- | --- | --- |
| 入口 | 十月官网允许原创、移植和已有项目，也允许维护非本人创建的旧项目；已有项目需本期实质新增 | 社区开发者主动报名，项目须已有一定可用性并持续维护 |
| 贡献者条件 | 官网要求可追溯的实质贡献，不要求项目由参赛者创建 | 章程 4.2 要求主要贡献者为参赛者本人，允许其他贡献者；不要求当季新建或个人独立完成 |
| 历史成果 | 不重复计入当期工作；此前参赛项目须有新的、独立可验证成果 | 以本届期间新增有效贡献/维护为主要依据，历史代码量与完成度不能替代新增贡献 |
| 支持与季度入池 | 官网说明月度支持及新项目通过后进入季度评选；旧项目衔接不能直接推定 | 季度维护与新项目基础共建激励分别列示；主动报名不等于已入围或获奖 |

来源：[十月官网](https://moonbitlang.github.io/Hackathon2026/#process)，并核对其[公开源码版本](https://github.com/moonbitlang/Hackathon2026/blob/a879c208b261ca500f65707d42504d06572fa9b0/src/App.tsx)；[正式章程第 4、5、6、7 节](https://bxup9uklfcb.feishu.cn/wiki/Dx4Bwd6D1i3GfHkajQCcF7SznEd)（页面显示 10 月 10 日修改）。官网写明十月报名/验收截止 2026-10-31，沿用报名表，最多三次提交，以通过审核前最后一次有效提交或修改时间为准。章程赛程仍显示九月日期，不能把九月日程套到十月；报名入口、模板及截止口径还须留意赛事群通知。

**申报定位：** “十月月赛：已有项目实质新增，已实现可验证 POS”。季度维护为另行确认的路径，不自称十月新建项目或已自动取得季度资格。官网要求加入赛事交流群并将群昵称改为 GitHub ID；这里未确认参赛者是否已完成。

## 初审材料与待确认事项

章程 5.1 要求人工撰写、一页 Markdown，包含项目方向/通用性、至少三个完整预期场景、核心功能、原创/移植/参考说明和公开仓库，并要求不少于十个有效提交。仓库已有超过十个非合并、非空提交，数量不替代赛事方对实质性的判断。[精简素材](十月黑客松申报草案.md)为 AI 辅助准备资料；[长篇说明](项目申报书.md)为详细支撑资料，均不代表正式人工申报书已完成。三个场景在 README、示例说明和可执行程序中提供输入、步骤、输出及限制。

正式申报仍需由参赛者独立改写并理解方案，核对九月原始拒绝通知及以下口径：

1. 九月未通过的 Fusekite 在十月修改原问卷重报时应选哪个字段？九月提交是否占十月三次额度？公开规则未明确跨期计数。
2. 月赛旧项目能否申请启动/完成支持，审核后的季度衔接是否须另报社区维护？官网自动入池条目写的是月度新项目。
3. 本项目有实质 AI 辅助；Git author/committer 只标识发布账号。季度“主要贡献者”认定与人工申报书要求的具体执行以赛事方答复为准。

本次未代提交报名表、联系赛事方或记录人工确认。九月拒绝原因仅据留存草案，不能代替原始通知；也没有赛事方已认可差异化或资格的证据。

## 基线、十月增量与当前验证

- 九月基线 [`3371536`](https://github.com/Lyhdsba/Fusekite/tree/3371536742257f3834f71120b9009dd3ef820539)：ROBDD、SAT、受限 QF_BV、精确 SOP、器件估算及三个电路示例。历史成果不重复计入十月。
- 十月功能增量：[`4cf0228`](https://github.com/Lyhdsba/Fusekite/commit/4cf0228)实现 POS 化简、独立结果类型、模式与求值；[`615c352`](https://github.com/Lyhdsba/Fusekite/commit/615c352)实现 POS 专用 BDD/SAT 验证、全部 6,561 个三输入含无关项规格 oracle 和 1,296 组候选/反例对照；[`9d3c9df`](https://github.com/Lyhdsba/Fusekite/commit/9d3c9df)补齐三个可运行 SOP/POS 场景。POS 已实现，不再列作计划。纯关系澄清文档不作为主要功能增量。
- 对照 MoonBDD 的固定版本仍为其公开主分支 `1c43647849d4b1033edb9743e45199da2746f3d4`；只读核对其 README/API/算法与签名，没有复制代码、布局或提交方式。[范围对比](MoonBDD与Fusekite范围对比.md)区分九月基线与十月新增，承认 ROBDD 重叠，不声称集成或生态唯一。
- 本轮复现了最新已完成的[远端 CI 失败（9d3c9df）](https://github.com/Lyhdsba/Fusekite/actions/runs/38624216996)：Moon `0.1.20261012` 格式化将 `Int` 改写为 `Int32`，后续检查未执行。本轮采用该官方 SDK 的规范格式并重新验证，结果见[开发记录](../DEVELOPMENT.md#october-initial-review-audit-2026-10-15)。历史失败记录保留，后续远端状态须看对应提交的实际运行。
- 公开仓库、默认 `main`、Apache-2.0 与 `moon.mod` 的仓库链接一致。当前跟踪文件经自动扫描未发现本机绝对路径、私密联系方式、凭据或内部任务指示；姓名/GitHub ID 为既有公开申报署名。此检查不等于完整历史或外部附件的隐私认证。
