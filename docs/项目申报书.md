## 二、项目简介

我是个人参赛者罗永铧。收到初审意见后，我将项目从单一的小规模化简工具扩展为 MoonBit 布尔推理基础库与组合逻辑规划工具。当前仓库新增了约简有序二叉决策图（ROBDD）管理器，支持固定变量序、唯一节点约简、AND/OR/XOR 运算、取反、赋值求值和规范节点等价判断；原有真值表 SOP 化简与电子器件估算保留为其上的一个有明确边界的应用场景。开发使用 AI 编程助手提供了实质性协助，具体说明见第十章。

本项目针对初审提出的功能边界和工程规模偏小问题，补充了可独立使用的符号布尔表示层，而非只增加若干真值表样例。ROBDD 把布尔函数表示为共享、约简的决策图；同一管理器、同一变量序下，函数规范化为同一个节点，可执行布尔组合与等价检查。项目还使用该表示对 SOP 化简结果做独立的等价核验，并在 16 变量奇偶函数测试中验证最终可达图保持线性节点量级。原有精确化简器仍限于 8 变量，不把 ROBDD 描述为 SAT/SMT，也不宣称可替代 Z3：当前尚无 CNF 求解、SMT 理论、冲突学习或任意公式性能保证。

项目名称 Fusekite 取意于把逻辑化简结果连接到可检查的实验规划步骤。它不是完整的 EDA 软件，也不替代电气设计审核；目标是在清楚声明边界的前提下，为学习和早期方案比较提供一个轻量、透明的工具。

## 三、问题与项目价值

在数字逻辑学习中，化简结果的正确性和电路实现的可行性是相连但不同的两个问题。表达式在真值表上等价，并不自动意味着器件数量估算完整，也不代表芯片引脚、电压阈值、驱动能力、时序和负载条件已经满足。

Fusekite 将这两层信息分开呈现：
1. 先验证逻辑函数并求解 SOP 覆盖；
2. 再按明确的直接门级模型计算数量，最后依据来源清楚的器件目录折算整片封装数。

项目的价值有两层：ROBDD 层提供一个可复用、可测试的 MoonBit 符号布尔基础能力；电子规划层将小规模函数化简结果连接到门数和器件目录估算。使用者既可以组合变量节点验证逻辑，也可比较真值表、SOP 项、基础门数量和封装余量，并清楚知道估算遗漏了哪些实际工程因素。

## 四、核心功能与当前实现

### 4.1 真值表输入和边界校验

- 接受 1 至 8 个输入变量的单输出函数。
- 以无符号二进制行号表示真值表；第一个输入变量对应最高位。
- 校验最小项和无关项是否越界、重复或相互重叠。
- 未列入最小项或无关项的行按规定输出 0 处理。

### 4.2 Quine–McCluskey 化简和精确覆盖

- 按轮次合并相差一个有效位的项，并记录素蕴含项。
- 无关项可参与合并，但只覆盖无关项的项不会作为有效输出项保留。
- 构造必需输出行到候选素蕴含项的覆盖关系，识别本质素蕴含项。
- 对未覆盖行进行确定性的精确覆盖搜索；结果按项数、文字数和稳定的模式字典序排序，确保相同输入得到可重复的选择结果。
- 当前实现的输入上限是 8 个变量，项目不宣称对任意规模逻辑函数提供无界性能保证。

### 4.3 结构性门数和器件目录估算

- 依据直接两级 SOP 结构，将乘积项按二输入 AND 树、项间求和按二输入 OR 树估算。
- 对需要的输入反相信号按变量共享计数。
- 使用小型 SN74HC00、SN74HC04、SN74HC08 和 SN74HC32 目录记录逻辑功能及每片通道数，并按器件系列分别向上折算封装数量。
- 封装数折算用商和余数计算向上取整，避免通过加法求整时发生溢出；`GateCost::new` 会拒绝负数计数及总数超出 32 位有符号整数范围的数据。
- 目录记录基于制造商数据表中的逻辑功能和通道数；精确封装后缀、供货、价格、时序、负载和跨厂商兼容性不在当前估算范围内。

### 4.4 可运行示例

仓库提供三个带独立期望输出向量的组合逻辑示例：双条件传感器互锁、BCD 七段显示器 a 段逻辑、三输入多数/告警函数。示例说明输入约定、真值表、化简结果和直接门数，测试会将化简结果与预先列出的期望向量逐行比较。BCD 示例中的无关项仅在输入保证为有效 BCD 的假设下成立。

### 4.5 ROBDD 布尔推理基础

- 以固定变量序的 ROBDD 管理器构造变量节点；0 和 1 分别代表假、真终端。
- 通过 `low == high` 约简规则和唯一节点查找合并相同子图；通过带缓存的 Shannon 展开实现 AND、OR、XOR，并支持取反。
- 支持对布尔赋值求值、统计最终根可达节点和在同一管理器中按规范节点标识判断等价。
- 提供 `verify_sop_with_bdd`，在屏蔽无关项后独立核验选出的 SOP 是否与指定真值表一致；三个电路示例均执行该检查。
- 管理器支持 1 至 32 个变量，BDD 的节点数在最坏情况下可能指数增长，且当前查找结构使用线性扫描。该模块不是 SAT/SMT 求解器；当前不包含 CNF/DIMACS 输入、冲突学习、理论求解或 Z3 兼容接口。

## 五、技术方案与项目结构

项目使用 MoonBit 原生类型和测试组织实现，没有移植外部逻辑综合引擎。基础层为固定变量序 ROBDD 及布尔运算；应用层包括输入规格验证、素蕴含项生成、覆盖表建立、必选项提取、精确覆盖选择、BDD 等价复核、门数估算和器件封装折算。覆盖搜索以有效上界和已选项状态为基础进行分支，并使用未覆盖行的覆盖能力下界剪枝；结果排序规则写入设计说明，避免依赖容器偶然迭代顺序。

代码按问题边界拆分：
- **核心包（根包）：** `bdd.mbt` 实现符号决策图管理器；其余核心文件表达真值表规格、化简、覆盖选择和门数模型；
- **器件目录包（`parts/`）：** 保存 74HC 器件目录及封装折算；
- **电路示例包（`circuits/`）：** 提供电路示例和独立期望向量验证；
- **演示程序包（`cmd/main/`）：** 提供可运行命令行演示。

仓库配置了格式检查、类型检查、测试和 GitHub Actions CI 工作流。该布局强调从逻辑模型到估算输出的可检查链路，不采用大型 EDA 工具的插件式结构。

## 六、测试与验证

当前自动化测试包含输入校验、化简与覆盖边界、数值溢出保护、器件封装向上取整、ROBDD 规范化与布尔运算、非法节点/赋值边界、SOP 的 BDD 等价核验和示例真值表核对。16 变量奇偶函数用例检查 ROBDD 表达相对完整真值表的紧凑性；对于 3 个输入变量，测试使用独立子集 oracle 对全部 256 个布尔函数核对最小覆盖选择；另有稀疏 8 输入用例覆盖高位及行号边界。项目的 CI 工作流执行格式检查、警告视为错误的类型检查、测试、构建及演示程序运行。

以上是软件层面的自动化验证，不表示已完成实体面包板实验、逻辑仿真或电气安全认证。正式提交前，我将亲自从干净检出复现检查命令，并按实际选定的芯片封装查验当前数据表。若后续添加实物或仿真验证，应一并提供电路图、器件型号、测试条件和观察结果，不以估算替代测试证据。

## 八、项目特色与差异化

1. **逻辑到器件估算的边界清楚：** 化简结果、结构性门数和器件封装估算分别建模，不把逻辑等价误称为可直接投板的电路方案。
2. **小规模精确求解：** 通过明确的 8 输入上限换取可解释、可重复的精确 SOP 选择，并以穷举小规格 oracle 验证算法结果。
3. **面向基础逻辑场景：** 示例涉及传感器互锁、BCD 显示逻辑和多数告警函数，覆盖课程逻辑与基础实验规划场景。
4. **来源和假设可追踪：** 器件目录注明制造商数据表来源；文档明示估算没有涵盖的电压、时序、扇出、功耗和实际布线因素。
5. **轻量的 MoonBit 原生实现：** 以 MoonBit 原生包、命令行示例和自动化测试交付，依赖与构建流程精简。
