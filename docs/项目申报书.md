## 二、项目简介

我是个人参赛者罗永铧。收到初审关于功能边界和工程规模的意见后，我将项目扩展为由 ROBDD、CNF/DPLL SAT 与电子组合逻辑规划组成的 MoonBit 布尔推理基础库。当前仓库除固定变量序的 ROBDD 管理器外，新增了 CNF 校验与规范化、布尔表达式 Tseitin 编码、带搜索预算的 DPLL 求解器，以及基于 SAT 反例查询的 SOP 等价检查。原有真值表精确化简和器件估算仍保留清楚的输入边界。开发使用 AI 编程助手提供了实质性协助，具体说明见第十章。

本项目针对初审提出的基础库扩展方向，增加了两种相互独立的符号推理表示。ROBDD 将函数表示为共享约简决策图；同一管理器和变量序下，等价函数规范为同一个节点。SAT 后端接受规范化 CNF、读取带边界校验的 DIMACS 文本，也可将常量、变量、非、与、或、异或表达式通过 Tseitin 约束线性编码为 CNF，再用确定性 DPLL 搜索满足赋值。SOP 验证器将化简结果与真值表规格构造成反例查询：SAT 返回具体输入反例，UNSAT 才报告在 cared rows 上等价；预算耗尽明确返回 Unknown。自动测试穷举了全部 256 个两变量 CNF，抽样另 1,024 个三变量 CNF 并穷举各自赋值，还将 SAT 结果与穷举 oracle、ROBDD 表示交叉比对。当前求解器尚无 watched literals、冲突学习、非时间顺序回溯或 SMT 理论；这是一套经过验证的基础实现，不宣称可替代 Z3 或处理工业规模实例。

项目名称 Fusekite 取意于把逻辑化简结果连接到可检查的实验规划步骤。它不是完整的 EDA 软件，也不替代电气设计审核；目标是在清楚声明边界的前提下，为学习和早期方案比较提供一个轻量、透明的工具。

## 三、问题与项目价值

在数字逻辑学习中，化简结果的正确性和电路实现的可行性是相连但不同的两个问题。表达式在真值表上等价，并不自动意味着器件数量估算完整，也不代表芯片引脚、电压阈值、驱动能力、时序和负载条件已经满足。

Fusekite 将这两层信息分开呈现：
1. 先验证逻辑函数并求解 SOP 覆盖；
2. 再按明确的直接门级模型计算数量，最后依据来源清楚的器件目录折算整片封装数。

项目的价值有三层：ROBDD 提供规范化符号表示，CNF/DPLL 提供可返回模型、反例或有界未知结果的 SAT 查询能力，电子规划层再将小规模函数化简连接到门数和器件目录估算。使用者可以将 SAT 用于布尔约束的满足性检查和具体反例定位，也可以比较真值表、SOP 项、基础门数量和封装余量，并了解各工具的资源限制。

## 四、核心功能与当前实现

### 4.1 真值表输入和边界校验

- 接受 1 至 8 个输入变量的单输出函数。
- 以无符号二进制行号表示真值表；第一个输入变量对应最高位。
- 校验最小项和无关项是否越界、重复或相互重叠。
- 未列入最小项或无关项的行按规定输出 0 处理。

### 4.2 Quine–McCluskey 化简和精确覆盖

- 按轮次合并相差一个有效位的项，并记录素蕴含项。
- 无关项可参与合并，但只覆盖无关项的项不会作为有效输出项保留。
- 构造必需输出行到候选素蕴含项的覆盖关系，识别本质素蕴含项。
- 对未覆盖行进行确定性的精确覆盖搜索；结果按项数、文字数和稳定的模式字典序排序，确保相同输入得到可重复的选择结果。
- 当前实现的输入上限是 8 个变量，项目不宣称对任意规模逻辑函数提供无界性能保证。

### 4.3 结构性门数和器件目录估算

- 依据直接两级 SOP 结构，将乘积项按二输入 AND 树、项间求和按二输入 OR 树估算。
- 对需要的输入反相信号按变量共享计数。
- 使用小型 SN74HC00、SN74HC04、SN74HC08 和 SN74HC32 目录记录逻辑功能及每片通道数，并按器件系列分别向上折算封装数量。
- 封装数折算用商和余数计算向上取整，避免通过加法求整时发生溢出；`GateCost::new` 会拒绝负数计数及总数超出 32 位有符号整数范围的数据。
- 目录记录基于制造商数据表中的逻辑功能和通道数；精确封装后缀、供货、价格、时序、负载和跨厂商兼容性不在当前估算范围内。

### 4.4 可运行示例

仓库提供三个带独立期望输出向量的组合逻辑示例：双条件传感器互锁、BCD 七段显示器 a 段逻辑、三输入多数/告警函数。示例说明输入约定、真值表、化简结果和直接门数，测试会将化简结果与预先列出的期望向量逐行比较。BCD 示例中的无关项仅在输入保证为有效 BCD 的假设下成立。

### 4.5 ROBDD 布尔推理基础

- 以固定变量序的 ROBDD 管理器构造变量节点；0 和 1 分别代表假、真终端。
- 通过 `low == high` 约简规则和唯一节点查找合并相同子图；通过带缓存的 Shannon 展开实现 AND、OR、XOR，并支持取反。
- 支持对布尔赋值求值、统计最终根可达节点和在同一管理器中按规范节点标识判断等价。
- 提供 `verify_sop_with_bdd`，在屏蔽无关项后独立核验选出的 SOP 是否与指定真值表一致；三个电路示例均执行该检查。
- 管理器支持 1 至 32 个变量，BDD 的节点数在最坏情况下可能指数增长，且当前查找结构使用线性扫描。ROBDD 模块只负责规范化符号表示和布尔运算；SAT 求解由后述独立 `sat/` 包提供。

### 4.6 CNF 与 SAT 基础库

- **CNF 规格：** 变量使用 1 至 4,096 的正整数编号，字面量正负号表示变量或其否定；构造时校验边界、复制输入数组、去重字面量和子句、删除重言子句，并保留空子句为矛盾。
- **表达式编码：** 提供常量、变量、非、与、或、异或表达式。Tseitin 编码为每个复合操作增加辅助变量并添加双向等价子句，再以根单子句要求公式为真；表达式变量上限为 256，编码变量上限为 4,096，编码访问节点上限为 100,000。
- **求解器：** 使用确定性 DPLL 与两观察文字传播队列；被赋值为假的观察文字只触发相关子句检查，观察位置可移动到其他非假文字。分支时选择第一个未满足子句中的首个未赋值文字，并按时间顺序回溯；返回完整可验证模型、Unsatisfiable 证明状态或搜索预算耗尽的 Unknown。搜索预算可配置且最多为 1,000,000 个递归搜索节点。
- **应用接口：** SAT 等价验证构造“期望函数异或候选 SOP”并屏蔽无关项。找到 SAT 模型时返回输入变量构成的反例；只有证明 UNSAT 才报告等价；非法解和 Unknown 使用不同结果分支。
- **工程边界：** 当前尚无冲突分析和学习子句、非时间顺序回溯、变量活动度启发式或 SMT 理论。求解复杂度最坏仍为指数级；当前确定性分支策略用于教学与可验证的小型约束示例，不宣称工业级性能或兼容 Z3。

## 五、技术方案与项目结构

项目使用 MoonBit 原生类型和测试组织实现，没有移植外部逻辑综合引擎。基础层由固定变量序 ROBDD、CNF 规格、Tseitin 编码和 DPLL SAT 求解构成；应用层包括真值表规格验证、素蕴含项生成、覆盖表建立、必选项提取、精确覆盖选择、BDD/SAT 两路等价复核、门数估算和器件封装折算。求解结果的 Unknown 状态避免将预算耗尽误报为 UNSAT。

代码按问题边界拆分：
- **核心包（根包）：** `bdd.mbt` 实现符号决策图，`sat_verify.mbt` 接入 SAT 反例查询；其余核心文件表达真值表规格、化简、覆盖选择和门数模型；
- **SAT 包（`sat/`）：** 独立提供 CNF 数据模型、布尔表达式 Tseitin 编码、DPLL 求解、模型校验和求解统计；
- **器件目录包（`parts/`）：** 保存 74HC 器件目录及封装折算；
- **电路示例包（`circuits/`）：** 提供电路示例和独立期望向量验证；
- **演示程序包（`cmd/main/`）：** 提供可运行命令行演示。

仓库配置了格式检查、类型检查、测试和 GitHub Actions CI 工作流。该布局强调从逻辑模型到估算输出的可检查链路，不采用大型 EDA 工具的插件式结构。

## 六、测试与验证

当前自动化测试包含 CNF 输入边界与规范化、DIMACS 正常和错误文档、DPLL 的模型/矛盾/预算状态、Tseitin 表达式赋值对照、全部 256 个两变量 CNF 的穷举 oracle、1,024 个三变量 CNF 的穷举赋值检查、相同 256 个两变量 CNF 的 ROBDD 交叉检查，以及三个电路示例的期望真值表、BDD 等价和 SAT 反例查询。另有 16 变量奇偶函数 BDD 紧凑性检查、3 输入全部 256 个布尔函数的最小覆盖子集 oracle 和稀疏 8 输入边界用例。上述均为软件层面的自动化验证，不代表外部参考求解器差分、工业 benchmark 或实体电路实验。

以上是软件层面的自动化验证，不表示已完成实体面包板实验、逻辑仿真或电气安全认证。正式提交前，我将亲自从干净检出复现检查命令，并按实际选定的芯片封装查验当前数据表。若后续添加实物或仿真验证，应一并提供电路图、器件型号、测试条件和观察结果，不以估算替代测试证据。

## 八、项目特色与差异化

1. **逻辑到器件估算的边界清楚：** 化简结果、结构性门数和器件封装估算分别建模，不把逻辑等价误称为可直接投板的电路方案。
2. **小规模精确求解：** 通过明确的 8 输入上限换取可解释、可重复的精确 SOP 选择，并以穷举小规格 oracle 验证算法结果。
3. **面向基础逻辑场景：** 示例涉及传感器互锁、BCD 显示逻辑和多数告警函数，覆盖课程逻辑与基础实验规划场景。
4. **来源和假设可追踪：** 器件目录注明制造商数据表来源；文档明示估算没有涵盖的电压、时序、扇出、功耗和实际布线因素。
5. **轻量的 MoonBit 原生实现：** 以 MoonBit 原生包、命令行示例和自动化测试交付，依赖与构建流程精简。
